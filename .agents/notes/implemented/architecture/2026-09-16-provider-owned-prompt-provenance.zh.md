# Agent Note: 提供方拥有提示来源身份

Status: implemented

[English](2026-09-16-provider-owned-prompt-provenance.md) | 中文

## 问题

Agent Loop 为每条系统提示和运行时上下文快照写入固定内置包名。因此，替换公开 systemPrompt 提供方后，记录仍可能指向并未拥有当前部署的提供方。来源标签也参与恢复，因为运行时上下文通过持久来源元数据识别所有权。

## 决策

SystemPrompt 提供来源身份版本 1、`sourcePlugin` 和不可变 `legacySourcePlugins`。配置指定当前包身份，以及恢复时明确接受的旧身份。默认保留原生包名且无别名。循环为系统提示和运行时上下文投影捕获选中提供方的身份。

提供方变化时，即使文本相同，系统提示协调也会发布正常的 surface 替换。运行时上下文识别配置中的旧快照，但先发布一次当前来源，再抑制重复更新。外部来源的快照不被认领。不重写已提交事件或迁移代，新消息仍可从 Session 日志重建。

沙箱指导接受部署 `runtimeName`，默认为 DSH；权限与升级行为保持不变。Product 包通过组合选择自己的提供方、persona 和环境指令。

## 考虑过的替代方案

前端别名会展示与日志记录不同的生产方。把 Agent Loop 复制到 Product 包会重复持久化和执行语义。只修改来源常量、不处理历史所有权，会丢失快照恢复能力，可能导致重复上下文或无法清理。提供方拥有身份可保留单一实现和明确的恢复规则。

## 后果

识别提示来源数据的消费者接受当前提供方及其支持的历史身份。公开能力版本允许下游提供方在处理请求前拒绝旧运行时。测试覆盖原生默认值、实际循环发出的来源、同文本提供方变更、旧来源恢复、外部来源隔离和不变的权限语义。
