# Agent Note: 部署组件归属

Status: implemented

[English](2026-10-09-deployment-component-ownership.md) | 中文

## Problem

已安装的包可以声明独立 Bundle，同时它的组件已由另一个选中的 Bundle 挂载。未选中这个独立层不代表组件停用。第二个包级开关可能重复组合，或卸载独立功能设置与持久化存储所依赖的载体。

## Decision

现有[插件管理器](../../../../packages/boot/plugin-manager/README.zh.md)接收 `managedBundles`，即默认空、按精确包名索引的字典。每项声明所需独立选择状态、可选的本地化标题及可选的提供者 `ownerBundle`。返回的部署策略与实际 Profile 选择和运行行阶段分开。它扩展[快照和行策略决策](2026-10-08-profile-plugin-snapshot-and-deployment-policy.zh.md)，不增加持久化投影或功能偏好。

Host 拒绝相反的选择、移除及已知包名的替换，包括禁用激活的安装。Registry 和本地目录身份在运行 pnpm 前检查。Git 与压缩包保留原有安装路径；解析出的受控包名被拒绝，并执行现有 Manifest 和锁文件回滚。该回滚不撤销 `node_modules` 中已下载或替换的文件，部署策略也不隔离不可信插件代码。

候选 Bundle 选择保留管理器的两个策略字典。表达式配置在候选比较时保留完整表达式身份；没有字面量策略字段的表达式不等于空策略。既存选择偏差不阻止无关扩展操作。修复只能恢复声明的选择状态。管理后端保护仍强于部署规则。

页面将命名的部署组件放在独立分组，显示本地化标题及实际运行行摘要。不提供独立包级开关、受部署管理行的开关或卸载动作；未受控组件行保留普通控制。选择冲突提供单向部署修复。即使包选择已经正确，可定位的受控行仍为陈旧启用状态提供同样修复。功能设置仍由各自页面负责；详情贡献可通过现有 Slot 跳转。

## Alternatives considered

**将所有已安装包都视为功能开关。** 包是否存在、Bundle 是否选中、组件是否挂载及功能是否使用是独立事实。

**只隐藏开关而没有 Host 策略。** 其他管理客户端仍可激活重复层或移除载体。

**保护所有扩展或替换安装事务。** 精确的部署归属保留普通扩展能力，并保持现有安装器及其限制。

## Consequences

部署只声明自己拥有的包和组合中已经内嵌的载体。未受控的可选和用户 Bundle 保留原有控制。操作者直接编辑的文件仍是独立配置来源；管理器提供修复，而不重置功能设置或存储。

## Verification

真实 Loader/Profile 测试覆盖内嵌组件挂载、重复激活拒绝、移除与替换保护、擦除策略的候选层、陈旧选择修复及无关扩展管理。Client 组件测试覆盖部署分组、竞争开关缺失及单向修复。
