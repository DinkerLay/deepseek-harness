# Agent Note: 原生静态活动与同行轮次摘要

Status: implemented

[English](2026-10-09-native-chat-turn-presentation.md) | 中文

## Problem

部署需要静态运行状态和紧凑完成摘要，同时保留原生分组、排序、展开及历史。失败和停止也需要已记录耗时；只显示失败标签会隐藏可用的时间证据。

## Decision

[Chat](../../../../packages/client/ui-chat/README.zh.md#grouped-rendering)拥有两项展示选项。`quietActivity` 显示静态运行文字与已用时间，不挂载图标或动画 Chat 标题。`inlineCompletedSummary` 在原生已结束轮次开关中加入一份静态类别摘要。两者默认为 false，部署可通过 Host 偏好或公开注入展示策略选择。`turnPresentationVersion` 标识完整 Client 契约。

轮次开关显示或隐藏符合条件的过程范围。分组完整标题及独立控件留在各自原始正文旁，保留原生顺序及展开状态。中间叙述仍位于原有分组之间，最终答复独立于过程保持可见。历史更新和工作详情模式变化保留现有容器，不需要 DOM outlet 或另一套展开 Store。

状态、耗时及总摘要使用内容字号设置。同行耗时沿用 UI 字体及等宽数字；长摘要省略，耗时文字保持可见。中间及最终 Assistant 回复保留相同的原生 Markdown 字体层级与回复间距。过程成员分类控制开合，不改变文字样式。

所有结束状态使用已记录的起止边界。边界缺失时省略时间，不用当前时钟估算不完整历史。运行时钟刷新保留单一稳定的状态播报。

## Alternatives considered

**替换 Chat View 或分组状态。** 为小范围布局选择把无关执行展示和回放行为转移给部署。

**把各组控件移到状态行。** 长轮次产生一排图标，控件与其正文及中间叙述分离。各组标题留在原位，可保留操作与内容的对应关系。

**在状态行重复每份分组文字。** 长轮次会重复标签并挤满窄框。一份静态总摘要保留工作概况，不增加操作入口。

## Consequences

原生 Session 事件和模型请求保持原样。静态选项不激活自定义图标贡献。已知失败和停止时间可见，未知时间保持缺失。只有最终答复的轮次没有工作摘要。聚焦测试覆盖六个独立分组、中间叙述、最终答复可见性、历史更新、模式变化、开合重置及计时清理。
