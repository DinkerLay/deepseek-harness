# Agent Note: 原生成员身份与执行保管

Status: implemented

[English](2026-10-05-native-member-executions.md) | 中文

## 问题

teammate 最初的 Session 地址标识 Task 归属和消息收件人。为了新上下文而到处替换此地址，会改写历史生产者并混淆迟到回调。每次换上下文都重建 roster 成员，还会消耗永久名字和历史名额。

公开空闲状态不排除维护工作，内存中已追加的事件也不证明检查点成功。任一观察单独都不足以允许启用替代执行。

## 决策

[原生 Team](../../../../packages/experimental/agent-team/README.zh.md) 在既有日志中保留原成员身份和执行代次。可选 Host 拥有者限制单个成员的协作准入，并将不透明进度附在同一次控制或绑定效果上。当前调用者从真实执行解析；历史作者和旧收据不改写。普通组合不安装此拥有者。

[接续管理器](../../../../packages/subagent/subagent/README.zh.md) 提供无输入准备和安静 Host 维护，保留父级、descriptor、Preset 与 catalog 归属，不请求模型。绑定与解除限制先占住前任，再进行串行 Team 核对。等待时不持有 Team 锁；即使解除限制已经提交，运行时占用也持续到维护归还。

休眠的前任通过 Core 独占的存储输入保管处理，不挂载旧 Preset。Core 在修复中断输入前校验来源并持有原 writer；Subagent 预留子会话并核对父子关系和 descriptor。仅当父级目录也没有记录时，缺失存储才表示尚未创建。已存在日志丢失、执行仍活跃或外部效果未确定时继续阻塞。普通恢复路径仍要求原 Preset 修订。

回执要求检查点成功。重试身份覆盖候选、成员预留及准确取消消息集合，重试不会取消后来消息。Profile 槽位效果更新当前关联，不改写最初应用目标。有界参考以资料保留来源，不携带旧批准或指令权限。

## 考虑过的替代方案

**每次换上下文都退队重建。** 需要不同成员时适用；需要不变配置、身份和归属，仅更换执行时不适用。

**执行绑定只放在产品层。** 原生 mailbox、roster、Task 准入和冷恢复将需要第二个权威来源。绑定归原生 Team，流程意图与进度归产品。

**用空闲或旧代拒绝证明静止。** 两者都不能排除维护、后台 Job 或外部效果。仍需真实占用和调用方负责的阻塞观察。

## 结果与代价

消费者区分成员地址与生产执行。重建不删除 Session、不退还永久名字、不扩大普通工具、不重放旧批准。卸载可选拥有者不会悄悄开放其已绑定执行。

投影、真实 JSONL 与接续测试覆盖写盘失败、旧代拒绝、候选重试、冷保管与维护竞态。客户端测试区分变更中与就绪，在响应不确定时保留请求身份。产品流程和真实模型验收仍独立于原生机制测试。
